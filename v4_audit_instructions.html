📖 ThaiQuran v4 Audit & Sync Operations Guide ⚡ 127 Chunks Pipeline 🛡️ Safety Guardrails 100%

คู่มือคำสั่งปฏิบัติการตรวจทานวรรคตอน อักขรวิธี และคำสั่งซิงค์ผลลัพธ์กระจายเข้าสู่ thai-quran-web อัตโนมัติเมื่อสิ้นสุดแต่ละ Session

📋 ตารางสรุปคำสั่งที่ใช้งานบ่อยที่สุด (Quick Command Reference)

การปฏิบัติงาน คำสั่ง PowerShell / Terminal ฟังก์ชันการทำงาน
1. ตรวจสอบความคืบหน้า (Dashboard) python scripts/v4_tracker.py ดู % ความคืบหน้า และไฟล์ที่ต้องตรวจถัดไป
2. ตรวจสอบสถานะเฉพาะญุซ (เช่น ญุซ 1) python scripts/v4_tracker.py --juz 1 แสดงตาราง Chunks ในญุซที่เลือก
3. ปรับใช้ผลแก้ไขจาก Clipboard
(หลัง Copy ผลจาก Gemini Chat)		 python scripts/apply_v4_fixes.py เช็ก Safety Gates, บันทึก Fixes, อัปเดต TSV Tracker ทันที
4. ทดสอบความปลอดภัยก่อน (Dry-Run) python scripts/apply_v4_fixes.py --dry-run ตรวจสอบความถูกต้องโดยยังไม่แก้ไฟล์จริง
5. บันทึก Chunk ที่ "ถูกต้อง 100% ไม่พบจุดผิด" python scripts/v4_tracker.py --mark 1 1 DONE "สำนวนสมบูรณ์" เปลี่ยนสถานะ Chunk เป็น DONE เมื่อไม่มีจุดแก้
6. พรีวิวซิงค์เข้าเว็บก่อน (Dry-Run) python scripts/sync_v4_to_all.py --dry-run ดูจำนวนอายะฮฺและจุดต่างที่จะอัปเดตเข้าเว็บ
7. จบ Session: ซิงค์เข้า Web + App + Git Push ทั้งหมด python scripts/sync_v4_to_all.py --push "Audit Juz 1 Chunk 1 done" แพ็กเกจ Master Deliverables, ซิงค์เข้า thai-quran-web, ซิงค์เข้า thai-quran-app (JSON + SQLite DB), และ Push ทุก Repo

🔄 วงรอบการตรวจทานประจำวัน (Step-by-Step Audit Workflow)

1เริ่ม Session: เช็กความคืบหน้าและเปิดไฟล์ถัดไป

เปิด PowerShell ในโฟลเดอร์ H:\gits\thai_quran_translation_v4 แล้วรันคำสั่งเช็กสถานะ:

PowerShell 
python scripts/v4_tracker.py

ระบบจะบอกว่าไฟล์ถัดไปที่ต้องตรวจคือไฟล์ใด เช่น audit_chunks/subchunks/juz_01_part1_1_1_to_2_43.txt

2ส่งให้ Gemini Chat ตรวจทาน

  1. เปิดหน้าต่าง Gemini Chat แล้วแนบไฟล์คู่มือ rules/V4_STANDARDIZED_RULES.md (แนบครั้งเดียวใน Session)
  2. แนบหรือวางเนื้อหาของ Subchunk ที่ต้องการตรวจ (เช่น juz_01_part1_1_1_to_2_43.txt)
  3. พิมพ์ข้อความสั่ง: "โปรดตรวจทานชิ้นข้อมูลนี้ตามคู่มือที่แนบ และส่งคืนผลลัพธ์เฉพาะรายการแก้ไข"

3นำผลลัพธ์มาบันทึกเข้าระบบ

เมื่อ Gemini Chat ตอบกลับมา ให้ Copy ข้อความผลลัพธ์ไว้ใน Clipboard แล้วสั่งรัน:

PowerShell 
python scripts/apply_v4_fixes.py
🛡️ สิ่งที่ระบบทำให้อัตโนมัติในขั้นตอนนี้:
1. ตรวจสอบว่าคำค้นหา (target) ตรงกับข้อความจริง 100% หรือไม่
2. ดักจับและปฏิเสธหากคำค้นหากำกวม (ปรากฏซ้ำมากกว่า 1 จุดในอายะฮฺเดียวกัน)
3. ตรวจสอบว่าไม่มีการตัดเชิงอรรถ [FN:X] ตกหล่น
4. บันทึกผลลงในฐานข้อมูลประวัติถาวร data/v4_manual_audit_fixes.json
5. อัปเดตตารางติดตาม v4_audit_tracker.tsv (ปรับสถานะเป็น DONE และบันทึกสรุปจุดแก้)
6. Re-export ไฟล์ Chunk นั้นใหม่ทันที

4กรณีอายะฮฺถูกต้องดีแล้ว (0 จุดแก้)

หาก Gemini ยืนยันว่าไม่มีจุดผิด ให้สั่ง Mark ว่าตรวจเสร็จแล้วด้วยคำสั่ง:

PowerShell 
python scripts/v4_tracker.py --mark 1 1 DONE "ตรวจทานแล้ว สำนวนสมบูรณ์ ไม่พบจุดผิด"

🏁 ขั้นตอนการจบ Session และซิงค์ผลลัพธ์เข้า thai-quran-web และ thai-quran-app

เมื่อคุณตรวจเสร็จสิ้น 1 Chunk, 1 ญุซ หรือต้องการหยุดพักงานประจำวัน ให้ใช้คำสั่ง Sync & Push แบบคำสั่งเดียว เพื่อกระจายผลลัพธ์ทั้งหมดเข้าสู่ทั้งเว็บแอป, โมบายแอป และ Git Remote อย่างปลอดภัย:

PowerShell (คำสั่งหลักเมื่อเลิกงานหรือจบ Session) 
python scripts/sync_v4_to_all.py --push "Audit Juz 1 Part 1 completed: applied verified spacing fixes"

⚙️ ลำดับการทำงานอัตโนมัติภายในคำสั่งนี้:

ขั้นตอน รายละเอียดการประมวลผล
1. Rebuild Master Deliverables รัน Phase 6, 5 และ 7 เพื่อคำนวณและแพ็กเกจไฟล์ Master Deliverables ล่าสุด (รวมถึง 01_thai_quran_translation_v4_master.json)
2. Sync เข้า thai-quran-web กระจายข้อความคำแปลและเชิงอรรถที่ผ่านการ Audit ล่าสุด เข้าสู่ thai-quran-web/src/data/thai_v3.json และ thai_footnotes.json โดยตรง
3. Sync เข้า thai-quran-app อัปเดตไฟล์ JSON assets/thai_v3.json, อัปเดตฐานข้อมูล SQLite assets/quran_offline.db (ตาราง verses คอลัมน์ translation_th), และซิงค์ assets/footnotes/thai_footnotes.json
4. Git Pull ป้องกันชน ตรวจสอบและดึง Git ล่าสุดจาก GitHub ของทุก Repo (V4, Web, App) ก่อนเสมอ
5. Git Commit & Push อัตโนมัติ สั่ง Commit และ Push การเปลี่ยนแปลงทั้งหมดของทั้ง 3 Repositories (thai_quran_translation_v4, thai-quran-web, thai-quran-app) ขึ้นสู่ GitHub Origin
💡 ต้องการตรวจสอบก่อนซิงค์จริง?
คุณสามารถเติมแฟล็ก --dry-run เพื่อดูพรีวิวก่อนได้ว่ามีอายะฮฺและเชิงอรรถกี่จุดที่จะถูกอัปเดตเข้าสู่เว็บ โดยยังไม่มีการแก้ไขไฟล์จริง: 
python scripts/sync_v4_to_all.py --dry-run

🛡️ กฎเหล็กและข้อควรระวังสำคัญ (Rule Zero & Guardrails)

คำเตือนสูงสุด (Rule Zero: ห้าม Overkill / ห้ามรื้อสำนวนโดยไม่จำเป็น):
อัลกุรอานแปลไทยฉบับสมาคมนักเรียนเก่าอาหรับฯ (King Fahad Complex) เป็นมรดกทางวิชาการศาสนาที่ผ่านการตรวจทานทางชะรีอะฮฺมาแล้วอย่างยาวนาน ห้ามแก้ไขเพียงเพราะความชอบส่วนตัว หรือต้องการเปลี่ยนคำไวพจน์ หากสำนวนเดิมถูกต้องตามหลักภาษาและสื่อความหมายได้สมบูรณ์แล้ว ให้คงเดิมไว้เสมอ

4 เสาหลักของการตรวจทาน V4:

  • 1. การเว้นวรรคตอน (Spacing & Cadence): ปลดคำที่พิมพ์ติดกันเป็นพรืด (OCR Glue) เช่น อัลลอฮฺพระผู้อภิบาล $\rightarrow$ อัลลอฮฺ พระผู้อภิบาล และเว้นวรรคช่วงประโยคให้อ่านสบายตา
  • 2. สถาปัตยกรรมวรรคตอน: ไม้ยมก (ๆ) ต้องเคาะหน้า-หลัง, วงเล็บ (...) ต้องเคาะนอก ไม่เคาะใน, เชิงอรรถ [FN:X] ต้องชิดกับคำและห้ามทำหล่นเด็ดขาด
  • 3. ตารางอักขรวิธีพินทุ (ฺ): อัลลอฮฺ, รอซูล, นบี, มลาอิกะฮฺ, อัลกุรอาน, กาฟิรฺ ฯลฯ และคำไทยตามราชบัณฑิตฯ (เช่น อินทผาลัม ให้คงมีสระอาไว้ตามขนบอัลกุรอาน)
  • 4. หลักเตาฮีดและความบริสุทธิ์ของสรรพนาม: Majestic We ใช้ "เรา" (ห้ามใช้ "พวกเรา"), บทดุอาอ์บ่าวใช้ "โอ้พระผู้อภิบาลของพวกเรา", ปลดราชาศัพท์ออกจากกาเฟรและรูปปั้น, ดักจับบั๊ก "ที่ทำการ" บนคำว่า ณ พระองค์

⚠️ กฎล็อกตำแหน่งคำ (Context Anchor Rule):

หากคำที่ต้องการแก้มีคำซ้ำกันในอายะฮฺเดียวกัน ห้ามระบุคำเดี่ยว ๆ โดด ๆ ให้ใส่คำแวดล้อมข้างหน้าหรือข้างหลังมาด้วย 1–2 คำ เพื่อให้จุดนั้นเป็นเอกลักษณ์เพียงจุดเดียวในอายะฮฺ มิฉะนั้นระบบจะปฏิเสธการแก้ไขทันทีเพื่อความปลอดภัย
